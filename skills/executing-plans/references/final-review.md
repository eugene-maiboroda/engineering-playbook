# Фінальна перевірка основним агентом

Після завершення задач зістав увесь результат зі специфікацією, планом,
Review Focus, журналом рішень і deferred findings. Перевір взаємодію
контрактів, відсутність зайвої функціональності й фактичні докази.

За погодженого незалежного review підготуй snapshot за
[review-snapshots.md](review-snapshots.md) та використай
[final-reviewer-prompt.md](../../subagent-driven-development/final-reviewer-prompt.md).
Не запускай додаткового агента лише тому, що він доступний. Якщо користувач
не обрав незалежний review або tool відсутній, виконай self-review й
повідом, що свіжої незалежної оцінки не було. Не підміняй обраний режим
самостійно при недоступності reviewer: уточни допустимий fallback.

Для finding перевір докази, реальний вплив і scope. Severity — рекомендація,
не автоматична істина. Не відкидай дефект лише через мовчання специфікації;
не додавай нову фічу під виглядом виправлення. Coverage/style самі по собі
не стають findings. Відсутність доступного контексту познач limitation.

Виконай один обмежений прохід погоджених виправлень Critical/Important,
перевіряючи змінений код доречними наявними засобами. Нові тести лише за
явним запитом. Minor поза scope запиши як deferred, не виправляй «заодно».
Якщо залишилися суттєві проблеми або перевірка failed, зупини завершення,
покажи користувачу відкриті питання й запропонуй наступну дію. Ліміт
проходу не означає дозвіл видати ненадійний результат за complete.

Повторний review потрібен за ризиком і погодженим режимом, не як
нескінченний цикл. Збережи всі findings і рішення; у фінальному повідомленні
назви виконане, перевірене, limitations, відкладене й user approvals.
Не видаляй журнал і snapshots автоматично та не виконуй Git mutations.
