# SQL bootstrap і зміни наявної схеми

Створи кореневий каталог sql/ і sql/sql-init.sql з актуальним повним DDL
порожньої БД. Не додавай Flyway або Liquibase. Якщо таблиць ще немає,
залиш пояснення призначення файла, не вигадуй бізнес-таблиці.

Для зміни наявних таблиць:

1. Онови sql-init.sql, щоб нова БД одразу отримувала актуальну схему.
2. Створи окремий sql/migration-<дата>-<назва>.sql для переходу вже наявної
   схеми. Перевір колізію назви, не перезаписуй стару міграцію.
3. Вкажи цільову БД, передумови, зміни й ризики для даних. Не запускай SQL
   автоматично через генерацію файла. Отримай дозвіл на застосування.
4. Запиши фактичне застосування й перевірки в progress. Тимчасовий файл
   міграції користувач видаляє після застосування; не видаляй його сам
   і не вважай застосованим лише за наявності файла.

Не запускай sql-init.sql на чинній БД як заміну міграції. Зберігай
spring.sql.init.mode=never: наявність каталогу sql не означає автоматичного
виконання Spring або Docker. У командах запуску опиши явну ініціалізацію
порожньої БД перед backend; не додавай destructive DROP або реальні credentials.
JPA ddl-auto=validate перевіряє схему, а не створює її.
