# Відновлення, batching та reports

## Відновлення

Спочатку прочитай спільний
[контракт журналу](../../executing-plans/references/execution-records.md).
Не re-dispatch завершені задачі за умови відповідності плану, snapshot і
доказів. Для незавершеної задачі перевір agent status, останній report
та лічильник fix rounds. Не запускай дубль, поки початковий агент ще
працює. Невідомість статусу — причина з’ясувати стан, не створити ще одного.

## Невеликі однотипні зміни

Кілька дрібних незалежних змін одного типу можна передати одному
implementer із явним переліком файлів, очікуваною зміною кожного й
спільним review. Не приховуй окремі результати або статуси задач у batch.
Зміни з окремими ризиками, рішеннями чи перевірками не об’єднуй лише
заради меншої кількості dispatch.

## Статуси report

- **DONE:** перевір actual evidence, підготуй snapshot і task review.
- **DONE_WITH_CONCERNS:** прочитай concerns. Питання коректності/scope
  розв’яжи до закриття; спостереження збережи для review.
- **NEEDS_CONTEXT:** надай потрібний дозволений контекст, без вигаданих
  відповідей. Суттєве невідоме уточни в користувача.
- **BLOCKED:** визнач причину: permissions, контекст, складність, розмір
  задачі або помилка плану. Зміни умови перед retry; нову модель/декомпозицію
  запропонуй відповідно до дозволів, не обходь обмеження самостійно.

Питання implementer — сигнал для аналізу, не причина примусити його
закінчити невизначений результат. Релевантні уточнення внеси в brief та
журнал, щоб їх отримав reviewer і наступні задачі.

## Cannot verify

Reviewer може не бачити unchanged код або cross-task зв’язок. Кожен
суттєвий Cannot verify потрібно розв’язати до complete: додатковий exact
контекст того самого snapshot або доречна перевірка implementer.
Якщо підтверджено gap — fix loop; якщо доказів бракує — needs_verification,
не автоматичний defect або success.

## Очікування

Поки агент працює, готуй наступні дозволені матеріали, але не реалізуй
залежні задачі або не змінюй reviewed source. Використовуй штатні
сповіщення й bounded waits; не роби частого polling без нової інформації.
Дотримуйся лімітів інструмента й підтримуй зрозумілий прогрес для людини.
